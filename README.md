# Genome Gene Explorer · 基因组序列提取与注释校验工具

一个纯本地运行的 Windows 桌面程序：**给定基因组 FASTA + GFF/GTF 注释，输入基因名或 ID，立刻看到这个基因的上下游、外显子、内含子、拼接后 mRNA、CDS 与 UTR 序列，并能用自己手上的参考 mRNA/CDS/蛋白序列做真实比对校验。**

- 不联网、不依赖任何在线数据库；
- 几十 GB 的基因组也只占几十 MB 内存（走 `.fai` 随机访问，不把全基因组读进内存）；
- 所有序列、坐标、链方向都可追溯到来源文件，界面上的每一段颜色都能在导出文件里找到对应坐标；
- 支持**把 5 个文件打成一个压缩包一次导入**，程序按内容（而非文件名）自动认出谁是基因组、谁是注释、谁是 mRNA/CDS/蛋白，并登记成本地数据集库（见 §5）。

### 2.2 方式二：双击 `start.bat`（从源码运行，日常改代码用这个）

`start.bat` 不假设你的电脑上只有一个 Python。它按下面的顺序找你机器上**已经装好依赖**的解释器，第一个合格的直接用来启动（不建虚拟环境、不联网、几秒进界面）：

1. 环境变量 `GGE_PYTHON` 指定的解释器；
2. 项目目录下的 `.venv\Scripts\python.exe`；
3. `py` 启动器登记的 3.13 / 3.12 / 3.11 / 3.10；

6. 随其他软件附带的解释器目录 `%USERPROFILE%\.workbuddy\binaries\python\versions\*`。

- 一个 Python 都没有 → 明确提示三条出路：装 Python / 用 2.1 的 exe / 用 `GGE_PYTHON` 指定路径。

## 4. 输入文件

| 类型 | 是否必需 | 格式 | 说明 |
| --- | --- | --- | --- |
| 基因组 FASTA | 必需 | `.fa` `.fasta` `.fna`（可 `.gz`） | 首次打开自动生成 `.fai` 索引；索引不能写时退回内存模式并提示 |
| 注释 | 必需 | GFF3 / GFF / GTF（可 `.gz`） | 自动嗅探格式；GFF3 用 `ID=`/`Parent=`，GTF 用 `key "value";` |
| 参考 mRNA | 可选 | FASTA | 用于校验拼接后的成熟转录本 |
| 参考 CDS | 可选 | FASTA | 用于校验编码区 |
| 参考蛋白 | 可选 | FASTA | 用于校验翻译结果 |

每个文件行都显示：路径、解析状态、解析结果（如「基因 11 / 转录本 21 / 外显子 21 · 链 18 / 序列 4 条」）。**任何文件缺失、格式错误、基因 ID 对不上，都会显式报告，不会静默跳过**。

注释解析能容错但会记警告的情况：坐标起止颠倒、`Parent` 指向不存在的转录本、只有 CDS 没有 exon（自动由 CDS 反推外显子）、缺少 gene 行、外显子相互重叠、列数不足 8 列、同一 seqid 多次出现等。警告集中显示在右下「基因信息 → 警告」。

> 懒得一个个点？把 5 个文件压成一个包，用 §5 的「导入压缩包」一次搞定，程序自己判断谁是哪个。

### 4.1 大数据集实测（NCBI 草鱼 HZGC01，GCF_019924925.1）

真拿整套 RefSeq 注释跑过一遍，不是估算：

| 文件 | 大小 | 载入耗时 | 结果 | 内存 |
| --- | --- | --- | --- | --- |
| 基因组 `.fna` | 863 MiB（893.22 Mb / 31 条序列） | **0.3 s** | 首次会建 `.fai`（约 1 分钟，之后就是秒开） | 只读索引，几十 MB |
| 注释 `.gff` | 524 MB / 178 万行 | **≈ 65–75 s**（机器忙时更久） | 31,801 基因 / 70,058 转录本 / 88.5 万外显子 | 峰值约 **1.26 GB** |
| 参考 mRNA | 259.8 Mb / 67,808 条 | 2.8 s | — | 随记录数线性增长 |
| 参考 CDS | 134.7 Mb / 59,323 条 | 1.8 s | — | 同上 |
| 参考蛋白 | 44.8 Mb / 59,198 条 | 1.1 s | — | 同上 |

载入期间进度条会依次走到 **15→70%（逐行解析，按已读字节算）→ 72%（建层级）→ 85%（挂外显子）→ 92%（自检）**，
实测一次加载里有 41 次进度更新，不会停在一个数字上等着。随时可以点「取消」。
注释的耗时几乎全在逐行解析上，是"读一次、之后全在内存里查"的模型：
换基因只需要重新提取那几 kb，不会再碰注释文件。

> 内存这一项是专门优化过的：最初版本在 15 GB 内存、剩 3 GB 的机器上直接换页到卡死
> （峰值 3.2 GB）。现在只给 gene/transcript 行保留完整属性，167 万个 exon/CDS 行的
> 临时字典全部丢掉，峰值降到 1.26 GB。规则写在 `gge/annotation.py` 的 `FeatureRow` 注释里。

拿同一份数据随机抽一个基因（`gene-LOC127515509`，位于负链 `NC_067220.1`）做三路校验，
三份参考**全部逐碱基完全一致**：

```text
mRNA    identical  XM_051899225.1              2464 / 2464 bp
CDS     identical  XP_051755185.1 对应的 CDS    1560 / 1560 bp
蛋白    identical  XP_051755185.1               519 / 520 aa（多的是终止符，比对时去掉）
```

> 蛋白这一路要特别说明：RefSeq 的 `protein.faa` 标题里只有蛋白 ID（`>XP_051755185.1 …`），
> 既没有转录本 ID 也没有基因 ID，光靠 ID 是匹配不上的。程序改用「已校验通过的参考 CDS
> 标题里写着的 `protein_id=`」来定位，唯一命中才采用（规则见 `docs/ALGORITHMS.md` §5.1）。
>
> 索引与解析的耗时/内存关系、以及为什么 mRNA 与 CDS 不能靠文件名区分，见 [`docs/ALGORITHMS.md`](docs/ALGORITHMS.md) §7 与 §9。

### 4.2 下次打开：自动回到上次的分析现场

关掉再打开，程序会把上次用过的 5 个文件**直接加载好**，并且回到上次查看的那个基因——
不需要再点「重新加载上次的文件」，也不需要重新搜索。左侧文件行会显示成 `✓ 3 条序列，共 893.22 Mb`，
而不是只有路径。

超大注释（比如 524 MB 的 RefSeq GFF，解析要 60–75 s）在这期间也是后台排队加载，界面可以正常操作、
随时能取消——**取消是真的能停下**：`read_rows` 每 5 万行查一次取消标记，实测 500 MB 的 GFF
在按下「取消」后 1.0 s 内结束，不会像旧版那样只能等它读完。加载过程中也不会弹「注释有提醒」
的对话框打断你，提醒留在状态栏与「数据校验」面板里。

想改回旧行为（只填路径、手动 `Ctrl+R` 加载），在「文件」菜单里取消勾选 **「启动时自动加载上次的文件」**，
选择会记在 `settings.json` 的 `auto_restore` 里。

| 情形 | 行为 |
| --- | --- |
| 5 个文件都在原位置 | 全部自动加载，回到上次的基因 |
| 某个文件被移动/删除 | 该行留空并标灰，其余照常加载，不报错打断启动 |
| 用 `--genome` / `--annotation` / `--import-bundle` 启动 | 以命令行参数为准，不做自动恢复 |
| 关掉「启动时自动加载上次的文件」 | 只把路径填回列表，状态写「上次使用（未加载）」 |

> 这一条是修一个真实问题：旧版重新打开时只在列表里填了路径（状态「上次使用（未加载）」），
> 用户看到文件名都在、以为已经就绪，一搜索却毫无反应——得自己找到「文件 → 重新加载上次的文件」才能用。

## 5. 数据集库：丢一个压缩包进来，自动认出哪个文件是哪个

一次分析往往要同时抱 5 个文件（基因组、GFF/GTF、mRNA、CDS、蛋白），文件名还常是 `assembly_v1.fna`、`sequences_a.fna` 这种看不出内容的名字。
所以这里做了个「数据集库」：**把一个压缩包拖进来，程序自己判断每个成员是哪个角色，解出来、登记、直接可用**。

### 5.1 三种入口

| 方式 | 操作 |
| --- | --- |
| 菜单 | **文件 → 导入压缩包（自动识别文件）…**（`Ctrl+Shift+I`） |
| 拖放 | 把 `.zip` / `.tar.gz` 直接拖进主窗口 |
| 命令行 | `python run_app.py --import-bundle D:\data\my_bundle.zip` |
| 打开库 | **文件 → 数据集库…**（`Ctrl+L`），双击一行即载入 |

支持的压缩格式：`.zip` `.tar` `.tar.gz`/`.tgz` `.tar.bz2`/`.tbz2` `.tar.xz`/`.txz`；
压缩包**里**的成员本身还可以再套一层 `.gz`/`.bz2`/`.xz`，会自动解开（BGZF/bgzip 的基因组例外，见 `docs/ALGORITHMS.md` 7.6）。
`.7z` / `.rar` 明确不支持——拖进来会提示先转成 zip，不会假装解开然后给你一个坏文件。

包内目录层级随便套，`__MACOSX/`、`._xxx`、`.DS_Store`、`README`、图片、日志这些非数据成员会被跳过，**并逐个列出跳过原因**。

### 5.2 自动识别靠什么

**只看内容，不看文件名。** 四类证据：

| 证据 | 怎么用 |
| --- | --- |
| 格式嗅探 | 首个非注释行以 `>` 开头 → FASTA；≥8 列 Tab → GFF/GTF；再按 `ID=`/`Parent=` 还是 `key "value";` 区分 GFF3 / GTF |
| 字母构成 | 统计 ACGTUN 占比，< 0.80 判为蛋白（蛋白 FASTA 里 R/K/L 这些字母会立刻把它暴露出来） |
| 与注释交叉验证 | FASTA 的序列名命中注释里的 `seqid` 集合 → 基因组；命中转录本 ID → 参考 mRNA/CDS |
| 长度吻合 | 把每条记录的长度与注释里"逐转录本外显子长度之和 / CDS 长度之和"比对；mRNA 吻合外显子和，CDS 吻合 CDS 和且长度能被 3 整除。**这是 mRNA 与 CDS 唯一可靠的区分依据**，两者都是核酸、都带转录本 ID |

文件名关键词（`genome`/`cds`/`pep`…）只给很低的分，改名骗不到程序，但也保留它作为"没别的证据时的微弱倾向"。
打分细节、阈值、采样上限见 [`docs/ALGORITHMS.md`](docs/ALGORITHMS.md) 第 7 节，库的表结构与删除归属见第 8 节。

下面是对 `examples/demo_bundle.zip` 的真实扫描输出——这个包的 5 个文件名是我**故意起得毫无信息量**的：

```text
压缩包：demo_bundle.zip（zip，10.6 kb，5 个文件）
  [基因组序列] demo_dataset/assembly_v1.fna  (FASTA, 3 条序列，21.0 kb)  核酸字母占 100.0%；文件名含 assembly；序列名与注释一致（chr1 等 3 条）
  [基因注释] demo_dataset/annotation.gff3  (GFF3, GFF3 · 基因 10 · 转录本 11 · 外显子 19 · CDS 18 · 序列 4)  内容为 GFF3 注释（9 列 Tab + 属性列）
  [参考 mRNA] demo_dataset/sequences_a.fna  (FASTA, 7 条序列，2.3 kb)  序列名命中转录本 ID（g1.1 等 2 条）；2 条记录长度与注释 mRNA 长度吻合（100%）；仅 29% 的记录长度能被 3 整除
  [参考 CDS] demo_dataset/sequences_b.fna  (FASTA, 3 条序列，1.2 kb)  3 条记录长度与注释 CDS 长度吻合（100%）；100% 的记录长度能被 3 整除
  [参考蛋白] demo_dataset/peptides.faa  (FASTA, 1 条序列，120 aa)  字母构成像蛋白（ACGTUN 仅占 28%）；文件名含 faa
  [跳过] demo_dataset/README.txt  系统文件或说明文件
  [跳过] __MACOSX/._junk  系统/版本控制目录
```

括号里的「判断依据」就是打分来源，界面上每一行都能看到，不需要相信黑箱。

### 5.3 识别不确定时会怎样

- 对话框每行都有「识别为」下拉框，可以手工改；**角色是独占的**，同一个文件不可能既当 mRNA 又当 CDS（选走之后原处自动变「未识别」）。
- 出现两个候选基因组/两个候选 CDS 时，只保留证据最强的那一个，其余降级为「未识别」，并在「查看扫描详情」里写明是被谁压下去的——**不会闷头挑一个**。
- 整个包里只有一个核酸 FASTA、又没有任何注释可交叉验证时，会按基因组处理，但置信度只有 0.3，且强制附一条「只能凭…当作基因组，请确认」的提示。
- 缺必需角色（基因组 / 注释）时「导入」按钮是灰的，顶部直接写「还缺：基因注释」，不会让你导进去一个残缺数据集。

界面样子见 `screenshots/07_bundle_import.png`（识别结果表 + 判断依据 + 可手工改的下拉框）与
`screenshots/08_library.png`（数据集库）。两个图都由 `python tools/screenshot.py` 真实窗口截取，可随时重跑。

### 5.4 导入之后放在哪

```text
%APPDATA%\GenomeGeneExplorer\library\
├─ library.sqlite                          数据集名、来源压缩包、基因/转录本数、导入时间、每个角色的文件路径
└─ datasets\<名字>_<YYYYmmdd-HHMMSS>\      解出来的实际文件（文件名已消毒，见下）
```

- 载入一个数据集 = 一次把 5 个文件行全部填好；窗口会记住上次用的数据集，下次启动自动恢复。
- **同一个压缩包再导一次会替换旧记录**（按来源路径判重），不会越导越多份副本。
- 成员名会先做消毒：拍平成 basename（防 `../..` 目录穿越 / zip-slip）、去掉 Windows 非法字符、`CON.fa` 这类保留名加前缀、重名自动加 `_2`。所以解包绝不会写到库目录之外。
- 解包前会检查剩余磁盘（按未压缩体积 × 0.35 + 128 MB 估算），中途取消或失败会把半成品目录**整个删掉**，不留残局。

### 5.5 删除：只删它自己的文件

「移除」只删 `library\datasets\` 下、且确实属于这个数据集的目录（实现上用 `os.path.commonpath` 做了归属校验）。
你自己另存的、放在别处的文件**不会被碰**。确认框也会明确区分这两种情况：
「将删除库内 5 个文件」 vs 「只从列表移除，文件保留在原处」。

## 8. 复制与导出

每个序列面板右上角：**复制**（选中片段或整面板原始碱基）、**FASTA**（带标准标题）、**导出**（存成 `.fa`）、**彩色文档导出**（导出带底色的 Word / 网页）。
「复制」出来的永远是**纯碱基**，不含颜色、行号、空格或任何装饰字符——要拿去跑 blast 就用它。

### 8.1 带颜色的序列文档（Word / 网页）

界面上那些底色（上游浅蓝、外显子绿、CDS 橙、UTR 紫…）原本只存在于屏幕里，导出的 FASTA 是纯文本。
**「彩色文档导出」按钮**（或菜单 `Ctrl+Shift+D`、或序列区右键）把它们写进文档：

| 能力 | 说明 |
| --- | --- |
| Word `.docx` | 文字级底纹（Word 的"字符底纹"），可以直接编辑、加批注、继续排版；不是截图，不是图片 |
| 网页 `.html` | 单文件、样式内联，浏览器打开即可，也可以直接用 Word 打开后另存为 docx |
| 复制为彩色序列 | 序列区右键 → 复制成 HTML 富文本，粘到 Word / WPS 就是带底色的表 |
| 三种着色 | 按区域（默认，与界面完全一致）、区域背景 + 碱基字母色、只按碱基（A/T/G/C） |
| 排版 | 每行 20–200 bp 可调（默认 60）、每 10 bp 一个空格、字号 6–14 pt、**默认不带左侧坐标列** |
| 内容 | 标题、基因/转录本/坐标/长度等元信息、颜色图例、每个面板的小标题与备注、逐行序列 |

细节：

- **坐标列默认不导出**：贴到论文/报告里通常不需要行号，左边那一列只会让整块序列往右偏。
  需要按位置核对时，在导出对话框里勾选「每行左侧显示坐标列」（选择会被记住）。
  打开后坐标也不是从 1 数：正链用块自己的基因组起点递增，负链从起点往小坐标走，拼接的 mRNA/CDS 用转录本内位置
  ——和界面左栏一模一样（同一份 `Block.first_coord`）。
- **颜色取自界面配色**：在「视图 → 配色设置」里改过的颜色，导出的文档跟着变。
- **文件大小**：按区域着色时，一段连续外显子只写 1 个文字块，50 kb 的面板也只有几百 KB；改成"碱基字母色"后每个碱基可能各成一块，体积大约十几倍。面板上会实时显示「Word 文件约 X KB / MB」，超过 20 万 bp 会提醒你先换成区域着色。
- 序列行里的空格是**分组空格**，不带底纹，所以色块之间的 10 bp 间隔一眼可见。
- 对话框样子见 `screenshots/09_doc_export.png`：上方勾面板（每个都标了长度，空面板自动置灰），
  中间调着色/每行 bp/字号，下方实时算「共几个面板 / 多少 bp / 约多少行多少页 / Word 约多大」。

### 8.2 纯文本导出

顶部「适配 / 导出图」：结构图可存 PNG（位图）或 SVG（矢量，投稿/放大不失真）。

菜单里的批量能力：

| 功能 | 位置 | 产物 |
| --- | --- | --- |
| 复制基因基本信息 | 编辑 → 复制基因基本信息 | 纯文本（基因、坐标、转录本、外显子数等） |
| 导出当前基因全部序列 | 文件 | 一个 `.fa`，含所有面板序列 |
| 导出当前转录本所有片段 | 文件 | TSV / CSV（片段类型、编号、坐标、长度、序列） |
| 批量导出多个基因 | 文件 | 每个基因一份 FASTA + `_batch_summary.csv` + `_batch_problems.tsv` |
| 导出校验报告 | 文件 / 校验卡片 | 文本报告（长度、一致性、差异位点、判定） |
| 导出彩色序列文档 | 文件 / 面板「彩色文档导出」/ 右键 | `.docx` 或 `.html`，带底色与图例（坐标列可选，默认关） |
| 导出数据集压缩包 | 文件 / 左侧「打包导出」 | 一个 zip（含 `gge_dataset.json` 清单），下次一键导入 |

FASTA 标题格式固定为：

```
>基因ID|转录本ID|序列类型|坐标(链)|len=长度|附加说明
```

实际例子（取自示例数据，可以自己导出核对）：

```
>g1|g1.1|genomic|chr1:501-2300(+)|len=1800
>g1|g1.1|upstream|chr1:501-1000(+)|len=500
>g1|g1.1|exon|chr1:1001-1200,1401-1550,1701-1800(+)|len=450|segments=3
>g1|g1.1|CDS|chr1:1051-1200(+)|len=150|cds1
>g1|g1.1|mRNA|chr1:1001-1200,1401-1550,1701-1800(+)|len=450|spliced_segments=3
>g1|g1.1|UTR|chr1:1001-1050,1761-1800(+)|len=90|segments=2
```

要点：

- **坐标永远是这一条序列自己的基因组区间**，不会拿基因整体区间顶替——所以上游序列的标题是 `501-1000` 而不是基因本体的 `1001-1800`；
- 拼接序列（完整 mRNA / 完整 CDS）把所有片段的区间按顺序列出（超过 4 个用 `,+N` 表示还有几个），并标注 `spliced`，**不会**把拼接后的位置当成基因组坐标；
- 片段级导出额外带 `exon1` / `intron2` / `cds3` 这类序号，同名的多条记录不会混淆；
- `len=` 是真实序列长度，可直接用于核对。

序列类型取值：`genomic` `upstream` `downstream` `exon` `intron` `mRNA` `CDS` `UTR`。

## 9. 参考序列校验

加载参考 mRNA/CDS/蛋白后，程序会：

1. **按 ID 打分匹配**，而不是按文件顺序取第一条：转录本 ID 完全一致 > 基因 ID > 子串包含 > 基因 Symbol > 长度接近；同分多候选时状态为「需人工确认」，并列出全部候选；
2. 用 Biopython 全局比对（match 2 / mismatch −3 / gap open −6 / extend −1）做**含 indel** 的真实比对，而不是按位置逐个比；
3. 报告长度、一致率、错配数、插入/缺失碱基数、可定位的差异位点、读框、起始/终止密码子、内部终止密码子；
4. 状态四档：**完全一致 / 有差异 / 未匹配到参考 / 需人工确认**。

卡片上的下拉框可以手动指定用哪条参考记录重新校验；点「详情」看比对视图（差异位置高亮）、差异位点表、候选与说明。

> 程序只**报告**差异，**不会**为了“看起来一致”而修改任何提取出来的序列。可能的原因（参考序列来自不同转录本、注释版本不同、参考本身含测序错误等）只作为排查方向列出，不下结论。

## 14. 常见问题

**Q：提示「FASTA 与注释的 seqid 对不上」怎么办？**
程序会给出两边的名字列表和“是不是同一个染色体的不同写法”的猜测（`chr1` / `1` / `NC_000001.11`）。它**不会**自作主张替换，因为那会把序列取错位置。请把 FASTA 与注释统一到同一套命名（可用 `seqkit replace` 或 `samtools faidx` 改名）。

**Q：CDS 长度不是 3 的倍数 / 没有起始密码子？**
这通常是注释本身如此（不完整模型、伪基因、非 AUG 起始）。程序会在校验里标红并给出提示，但**不会**截断或强行改成 3 的倍数——那会掩盖真实数据问题。

**Q：注释文件里没有 UTR，为什么面板里却有 UTR 序列？**
NCBI/RefSeq 的 GFF 只发布 `gene / mRNA / exon / CDS`，**不包含 UTR 行**（草鱼这份注释里 UTR feature 数为 0），所以面板上的 UTR 是程序推导出来的，不是从注释里读的。界面上会明确标出这一点：
- 面板标题写「**UTR（推导）**」，标题栏右侧显示 `注释无 UTR · 推导值`（若注释里确实有 UTR 行，则显示 `注释有 UTR 行 · 此处仍按推导`）；
- 每段序列的标题也是「5′ UTR（推导）」「3′ UTR（推导）」，说明里写明依据，例如 `末个 CDS 终点 2,141,404 + 1 起算`；
- 导出的 FASTA / 彩色文档同样带这个标记，不会让下游使用者误以为它是注释内容。

算法：对每条转录本取「外显子范围 − CDS 范围」，位于第一个 CDS 起点之前的是 5′UTR，位于最后一个 CDS 终点之后的是 3′UTR；夹在首尾 CDS 之间、未被 CDS 覆盖的空隙不算 UTR（那是注释异常，校验会提示）。
以 `gdf9`（`XM_051859896.1`）为例：exon2 = `2,140,464–2,142,137`，CDS2 止于 `2,141,404`，于是 3′UTR = `2,141,405–2,142,137`（733 bp），5′UTR 为 4 bp；`4 + 1296 + 733 = 2,033`，正好等于参考 mRNA 的长度。想自己核对时，用「校验」把参考 mRNA 比一下即可（基因组是 soft-mask 的，UTR 里有小写碱基，属正常）。

**Q：上下游方向怎么看？**
一律按**转录方向**：正链基因的上游在坐标更小的一侧，负链基因的上游在坐标更大的一侧。面板标题和 FASTA 标题里都写了 `(转录方向)` 与 `(+)/(-)`，结构图上还有箭头指示转录方向。

**Q：基因组连续序列窗口里包含上下游吗？长度怎么算？**
包含。窗口区间取 `min(转录本起点, 上游起点, 下游起点)` 到 `max(转录本终点, 上游终点, 下游终点)`，因此**窗口长度 = 上游实际长度 + 基因长度 + 下游实际长度**（例如 `prlrb` 在上下游各 2000 bp 时是 2000 + 14809 + 2000 = 18809 bp）。长度在顶部「上游/下游」输入框里改，改完按 `F5` 重新提取；靠近染色体末端时按实际可用长度截断，并在校验里给出提示。窗口内是**正链书写**的连续序列，负链基因的上游色带出现在窗口右侧，这是正确的。

**Q：基因组很大，打开会卡吗？**
不会把全序列读进内存。首次打开只为建 `.fai`（几 GB 通常十几秒到一分钟，有进度与取消）。之后每次提取只读需要的那几 kb。

**Q：为什么某个面板是灰的/写着“无内含子”？**
单外显子转录本没有内含子，面板会显示“该转录本仅 1 个外显子，无内含子”，这是正常结果，不是错误。

**Q：压缩包里的文件识别错了 / 有几个显示「未识别」？**
先看「查看扫描详情」，每一行都写了判断依据（例如「3 条记录长度与注释 CDS 长度吻合（100%）」）。
确认是程序判错，就在导入对话框里把那一行的「识别为」改成正确的角色——角色是互斥的，改完另一行会自动让位。
最容易被判错的情况是：参考 FASTA 里只有 1~2 条记录（样本太少，长度吻合无从统计），此时以「序列名命中转录本 ID」为准；
如果连 ID 都对不上（比如参考用的是基因 ID 而非转录本 ID），程序会标「未识别」而不是硬猜——手工指定即可。

**Q：导出的序列想带颜色发到 Word 里，怎么办？**
面板右上角点「彩色文档导出」（或序列区右键「复制为彩色序列」）。两种用法：
① **导出文件**——菜单 `Ctrl+Shift+D` 或「彩色文档导出」按钮，选面板、着色方式、每行碱基数，得到 `.docx` 或 `.html`；
② **直接粘贴**——右键「复制为彩色序列」，到 Word 里 `Ctrl+V` 就是带底色的等宽表格，不用先存文件。
颜色与界面同源（改了配色设置，导出跟着变），坐标列也来自同一套逻辑，不是另画一遍。

**Q：关掉再打开，文件名还在但用不了？**
旧版确实是这样：只把路径填回列表（状态「上次使用（未加载）」），数据并没有加载，
一搜索只会弹「还没有加载注释文件」。现在打开时会把它们自动加载好、并回到上次看的基因，
左侧显示 `✓` 才算真的就绪。若某一行仍是灰色的「上次使用（未加载）」，说明那个文件被移动或删除了，
点该行的「…」重新选一下即可。也可以在「文件」菜单里关掉「启动时自动加载上次的文件」改成手动 `Ctrl+R`。

**Q：点了「导出」但没找到文件？**
先看状态栏与弹窗：成功时会提示「彩色序列文档已导出」并列出完整路径。
默认落点是「上一次导出用的目录」；没有记录时用系统的**文档**目录（不是程序目录），
所以文件一定在一个绝对路径下，不会出现"相对当前工作目录"这种看不见的位置。
如果对话框里手动改过路径，就按你填的那个位置找。

**Q：Word 里打开的彩色文档为什么没有颜色 / 颜色不对？**
先确认打开的是 `.docx` 或 `.html`，而不是把 `.docx` 改后缀成了 `.doc`（Word 会按纯文本打开）。
其他阅读器（WPS、LibreOffice、macOS 预览）对 OOXML 字符底纹的解析进度不完全一致；
遇到显示不对就换 `.html`——它用 `background-color` 内联样式，适用范围最广，Word 也能直接打开。

**Q：我自己一个个选的文件，下次还要重新选一遍吗？**
不用。**文件 → 导出数据集压缩包**（`Ctrl+Shift+E`），把当前加载的基因组/注释/参考序列打成一个 zip，
里面有一份 `gge_dataset.json` 记录每个文件是谁。下次「导入压缩包」选中它，按清单直接认回来，
不再猜角色、也不再把大注释重新统计一遍。

**Q：支持 `.7z` / `.rar` 吗？**
不支持。这两种格式要么需要非自由解压库、要么需要外部 exe，为了不引入“有时能解、有时解出坏文件”的不确定性，只做 zip 与 tar 家族。
拖进来会明确提示「如果文件是 .7z 或 .rar，请先解压再重新打包成 zip」，不会给你一个解了一半的坏数据。

**Q：导入压缩包会不会把我原来的文件覆盖掉？**
不会。程序只往 `%APPDATA%\GenomeGeneExplorer\library\datasets\` 里写，文件名会在拍平后自动去重（`a.fa` 与 `a.fa` 变成 `a.fa` / `a_2.fa`）；
压缩包里带 `../` 的恶意路径也会被拍平成普通文件名。你原本的文件从来不在写入范围内。

**Q：设置乱掉了想恢复？**
菜单 **视图 → 恢复默认布局**，或删除 `%APPDATA%\GenomeGeneExplorer\settings.json`。

**Q：双击 `start.bat` 报 `'cho' 不是内部或外部命令` / `'se' 不是…` / `The binding handle is invalid`？**
这是批处理文件的换行被改成了 **LF**（Unix 换行）。cmd.exe 读 LF-only 的批处理时会把 `if (...)` 块的边界算错，于是 `echo` 被截成 `cho`、`else` 被截成 `se`，中文提示的后半句还会被当成命令去执行（所以看到 `'，首次需要几分钟）...' is not recognized`）。
用记事本或 VS Code 打开 `start.bat`，右下角把行尾改成 **CRLF** 后保存即可；或者直接重新解压交付包（仓库里的 `.gitattributes` 已把 `*.bat` 钉成 CRLF，正常 clone 不会再出这个问题）。

**Q：`start.bat` 报 `No module named pip` / `No module named 'PySide6'`？**
旧版脚本直接用 PATH 上的 `python`，而你机器上排在最前面的可能是某个没装 pip 的解释器（例如 Python 3.14 装完后没勾 pip，或 Microsoft Store 的占位符）。现在的 `start.bat` 会遍历机器上所有解释器，挑一个真正装了 PySide6 的来用；如果都没有，就用现有的 Python 建 `.venv` 装依赖。想确认它挑的是谁：

```bat
python tools\doctor.py
```

实在不想折腾 Python，直接双击 `dist\GenomeGeneExplorer\GenomeGeneExplorer.exe`（不需要 Python）。

## 15. 已知限制

- 只处理 gene → transcript → exon/CDS 这层结构，不解析 `five_prime_UTR` 等显式 UTR 行（UTR 由 CDS 与 exon 的差集推导，更稳）；
- 不处理可变剪接的“外显子跳跃”之外更复杂的 `CDS` 分段嵌套（如 ribosomal_slippage、transl_except 仅作为属性保留，不参与翻译）；
- 比对超过 60 kb 的序列会退化为“前后缀锚定 + 中段粗比对”，差异定位精度下降（会在报告里标注 `coarse`）；
- 单次只在界面里展示一个基因；批量导出走独立对话框；
- 压缩包只支持 zip / tar（含 gz、bz2、xz 压缩）；`.7z` / `.rar` 需先转换；
- 数据集库是**本地单用户** SQLite（同一台机器同时开两个窗口各自写入，后写的覆盖，不做跨进程合并）；
- 自动识别的交叉验证依赖注释本身可用：若注释解析不出任何转录本，mRNA 与 CDS 只能靠「长度能否被 3 整除」区分，
  这种情况下会明显降低置信度并提示手工确认，而不是给一个看起来很确定的错误答案；
- 彩色文档是**逐碱基排版**的：按区域着色时体积与"结构变化次数"成正比（几万个 base 也就几百 KB），
  但切到"碱基字母色"后每个碱基都可能自成一个文字块，100 kb 以上建议改回区域着色或改用 HTML——
  界面上会实时估算体积并在 20 万 bp 时提醒；
- 彩色文档里不放结构图（结构图请单独「导出基因结构图」，PNG/SVG 更适合投稿）；
- 数据集清单只记角色与路径，不记"上次搜了哪个基因"；要保留分析状态请导出基因序列或校验报告。

## 16. 算法与坐标约定

**强烈建议在改动 `extract.py` / `validate.py` 之前先读 [`docs/ALGORITHMS.md`](docs/ALGORITHMS.md)**，里面写清了：

- 1-based 闭区间 与 0-based 半开区间 的唯一转换点；
- 负链为什么必须“先倒序再反向互补”；
- CDS phase 为什么只报告不裁剪；
- 参考序列打分的完整阶梯与歧义处理；
- 比对参数、identity 定义、indel 归类方向（谁相对谁多）；
- 压缩包内文件角色的打分表（四类证据、权重、阈值，以及 mRNA 与 CDS 的长度吻合判据）；
- 数据集库的表结构、按来源判重的规则、以及“只删自己文件”的归属校验；
- 性能设计（虚拟化绘制、后台任务、缓存键、扫描时的采样上限）。
